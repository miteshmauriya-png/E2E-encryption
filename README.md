1. During Registration / First Login

User signs up for the first time. Frontend (React) generates a public-private key pair.
Private Key → Saved securely in the browser's localStorage.
Public Key → Sent to the backend and stored in the database associated with that user.
Backend saves the public key but never receives or stores the private key.

2. On Subsequent Logins

App checks if the user already has a private key stored locally.
If yes → Just fetch the public key from the server (no need to regenerate).
If not →  (new device or cleared storage) → Generate new key pair and update the   public key on the server.

3. keys generated by different libraries work together only if you use standard formats:

Public Key → SPKI format
Private Key → PKCS8 format

If two libraries output keys in compatible formats (especially PEM), they can interoperate.

How it Actually Works in Messaging:
User A wants to send a message to User B:
User A takes User B’s Public Key (fetched from server)
User A encrypts the message using User B’s Public Key
Sends the encrypted message to the server
User B receives the message:
User B uses their own Private Key (stored only on their device) to decrypt the message.
